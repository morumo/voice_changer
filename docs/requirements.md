# 要件定義

## Goals

- マイク入力音声をリアルタイムで変換し、仮想マイクとして Discord / Google Meet / Zoom 等で利用できる
- 変換レイテンシを最小化する（目標: < 50ms）
- 完全ローカル動作（外部 API・有料サービス不使用）
- Mac 対応（将来的に Windows も対応）
- OSS として GitHub 公開できる構成にする

## Non-Goals

- クラウドや外部サービスを使った変換
- スマートフォン対応
- 録音済みファイルのバッチ変換（リアルタイム変換のみ）
- 初期バージョンでの ML ベース変換（Phase 3 以降）

## 機能要件

### エフェクト

| エフェクト | 説明 | Phase |
|-----------|------|-------|
| 男声 → 女声変換 | ピッチ＋フォルマントシフトの組み合わせ（プリセット） | 1 |
| 女声 → 男声変換 | 同上（逆方向） | 1 |
| ロボット | リングモジュレーション | 1 |
| エコー | ディレイバッファによる残響付加 | 1 |
| ピッチ調整 | 半音単位での微調整 | 1 |
| フォルマント調整 | スペクトル補間による声道長変換 | 1 |
| ML ベース変換 | RVC / WORLD Vocoder による高品質変換 | 3 |

### セットアップ

- 起動時に BlackHole（仮想オーディオドライバ）の有無を自動検出する
- 未インストール時はインストーラを自動ダウンロード・実行するセットアップフローを提供する
- BlackHole は MIT ライセンスのため同梱・配布可能

### 操作 UI

| Phase | UI |
|-------|----|
| 1 | CLI（コマンドライン） |
| 2 | デスクトップ GUI（クロスプラットフォーム対応） |

### 入出力

- **入力**: システムに接続されたマイクデバイスを選択可能
- **出力**: BlackHole 仮想デバイスへ出力（Discord 等はこれをマイクとして認識）
- **モニタリング**: 変換後の音声をスピーカーでリアルタイム確認できる（任意）

## 非機能要件

| 項目 | 目標値 | 備考 |
|------|--------|------|
| エンドツーエンドレイテンシ | < 50ms | OLA 実装により実測値 ≈ 47ms（詳細は下記） |
| バッファサイズ | 256 samples（44100Hz 時に約 5.8ms） | `config/default.yaml` で設定 |
| 対応サンプリングレート | 44100Hz | 48000Hz は未検証 |
| 対応チャンネル数 | モノラル（変換処理）、ステレオ（出力） | |

### レイテンシ内訳

OLA（Overlap-Add）方式の DSP エフェクトは、ブロック境界をまたいで大きな分析フレームを使う。
バッファサイズ（HOP=256）とフレームサイズ（FRAME=2048）の差分がウォームアップレイテンシとなる。

```
バッファ蓄積 (256 samples @ 44100Hz)  ≈  5.8ms
OLA ウォームアップ (FRAME - HOP = 1792 samples)  ≈ 40.6ms
出力バッファ書き込み  ≈  0.5ms
合計  ≈ 47ms
```

> 目標の 50ms 以内は達成しているが、理想値（20〜30ms）を超えている。
> 高品質な DSP（位相ボコーダ・スペクトル補間）とレイテンシのトレードオフとして受け入れる。
